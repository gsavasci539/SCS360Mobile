# Native staff leave API checkpoint — 13 November 2026

Both native navigation paths now retain the existing Kotlin staff screen inside a scoped API wrapper. It loads real leave/duty records and sends canonical staff leave POST and review PUT DTOs. Acknowledgement is checked against the requested actor/dates/type/reason/day count and a fresh server list. Local leave IDs, local approvals, simulated notifications and fabricated review comments were removed from the ViewModel workflow. Scope changes cancel stale results; uncertain writes are not automatically repeated.

The form starts with blank dates, derives calendar days, requires a reason, scrolls within a bounded viewport with IME padding, preserves its dialog until successful server readback, and shows failures. Review controls require the actual user.write permission. The wrapper uses user.read for listing/own leave requests, matching the API. The server remains authoritative for permissions and record scope.

Validation: **6 unique native passes** (5 scoped HTTP client contracts, 1 Compose/Robolectric UI scenario) and a separate temporary-SQLite FastAPI contract **1 passed, 1 PostgreSQL variant deselected**. The UI fixture is 640x360 dp landscape at 1.5 font scale: blank dates/disabled submit, editable fields with scrolling, calendar day calculation, dialog retained after submit and closed only after acknowledgement revision. Native contracts cover canonical payloads/readback, mismatched actor, lost acknowledgement without retry, stale scope/invalid dates and canonical duty fields without invented dates/subjects.
